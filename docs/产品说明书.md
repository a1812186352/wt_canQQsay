# 小Q（QQ Agent）— AI 智能聊天管家 产品说明书

---

## 模块一：用户与场景

### 目标用户

| 用户画像 | 特征描述 |
|----------|----------|
| 高频社交用户 | 日均 QQ 消息 50+ 条，穿梭于私聊、群聊之间，信息过载，容易遗漏重要消息和承诺 |
| 社恐/沟通焦虑者 | 打字时反复斟酌措辞，担心表达不当，需要"翻译"自己想说的话 |
| "忘了回"型用户 | 看到消息想着"等会儿回"，然后永远忘了，朋友积累了怨气而自己浑然不觉 |
| 效率导向的职场人 | 多个项目群同时活跃，需要快速提取关键信息、待办事项和决策结论 |

### 用户痛点

| 痛点 | 现状 |
|------|------|
| 消息遗漏 | 99+ 未读时直接放弃，重要消息石沉大海 |
| 回复拖延 | "已读不回"成为社交摩擦的主要来源，但用户并非故意，只是忘了 |
| 表达困难 | 想拒绝、想委婉、想幽默，但打出来的字总是不够好 |
| 群消息焦虑 | 群里聊了 500 条，翻不动也看不完，不知道跟自己有没有关 |
| 记忆断片 | "上次你说那个餐厅叫什么来着？" — 聊天记录能搜到但懒得翻 |

### 使用场景

| 场景 | 描述 |
|------|------|
| **日常聊天辅助** | 私聊中，小Q 感知对话上下文，提供 3 个不同风格的回复建议（简洁/热情/幽默），一键选用 |
| **话术润色** | 用户在输入框打好草稿，小Q 帮忙优化表达——把"那不行"变成"嗯嗯了解了，不过我们可以再想想别的方案？" |
| **未回复提醒** | 用户看了消息但超过设定时间（10/15/30/60分钟）还没回复，小Q 主动弹出提醒："你有一条来自小明的消息还没回复哦，已经 30 分钟了" |
| **群聊精华提炼** | 爬楼太累？小Q 帮你提炼：聊了什么话题、有什么待办、定了什么决策 |
| **联系人记忆** | 小Q 持续记录每个授权好友的聊天内容，消息累积到阈值自动生成对话总结，形成"这个人说过什么"的完整画像 |

## 模块二：产品设计

### 产品概述

**小Q** 不是一个需要"打开"的 AI 应用，而是嵌入 QQ 聊天界面的智能管家。它静默地观察、理解和记忆，在用户真正需要时主动出现——提供回复建议、发送未回复提醒、提炼聊天精华。

产品定位：**从"工具"升级为"伙伴"** — 不只是执行指令，而是有记忆、有判断、有温度地陪伴用户完成社交。

### 核心功能

| 功能 | 说明 | 触发方式 |
|------|------|----------|
| 智能回复建议 | 基于对话上下文和联系人画像，生成多风格回复 | 悬浮球一键触发 |
| 话术优化 | 把生硬/直接的话润色为委婉得体的表达 | 输入框写好+悬浮球触发 |
| 精华提炼 | 从聊天记录中提取关键话题、待办、决策 | 手动触发 |
| 未回复消息提醒 | 已读超时未回复时主动推送提醒 | 自动（需用户授权） |
| 自动内容总结 | 消息累积到阈值后自动生成对话总结 | 自动（需用户授权） |
| 联系人画像 | 从对话中学习沟通风格、偏好话题、个性特征 | 自动（需用户授权） |
| 按联系人权限 | 每个好友独立控制：是否记录、是否总结、是否提醒及提醒时长 | 用户设置 |

### 交互流程

```
用户打开 QQ → 选择联系人聊天
     │
     ├── 输入消息 → 发送 → 小Q 记录（已授权时）
     │                      │
     │                      └── 消息累积到阈值 → 自动生成内容总结
     │
     ├── 点击悬浮球 → 选择 Agent 功能
     │    ├── 智能回复建议 → 小Q 分析上下文 → 生成多风格回复 → 用户选用
     │    ├── 话术优化 → 小Q 润色输入框内容 → 用户选用
     │    └── 精华提炼 → 小Q 总结聊天要点
     │
     ├── 打开聊天（已读）→ 开始计时
     │    └── 超时未回复 → 小Q 主动推送提醒（需用户开启）
     │
     └── 切换回小Q → 查看所有授权联系人的记忆总览、近期推送
```

### 创新与差异化

| 维度 | 传统 AI 聊天工具 | 小Q |
|------|-----------------|-----|
| 定位 | 命令行式问答 | 嵌入聊天的智能伙伴 |
| 触发 | 用户主动唤醒 | 主动感知 + 被动响应 |
| 记忆 | 单次对话遗忘 | 按联系人持久记忆 |
| 权限 | 无差别获取 | 按联系人精细授权 |
| 情感 | 无 | 学习沟通风格、适配个性 |
| 隐私 | 数据上云 | 全部本地存储，仅 LLM 调用走 API |

## 模块三：AI 能力

### AI 在产品中的核心能力

| 能力 | 说明 | 对应功能 |
|------|------|----------|
| **对话理解** | 从聊天记录中提取关键信息：话题、意图、情绪、待办事项 | 精华提炼、内容总结 |
| **上下文感知** | 理解当前对话在整体关系中的位置——"上次聊到哪了"、"之前答应过什么" | 联系人记忆、智能回复 |
| **个性化回复生成** | 结合联系人画像（性格、关系、沟通风格），生成贴合语境的回复 | 智能回复建议 |
| **话术转换** | 识别生硬/直接的表达，润色为委婉得体的说法，保持原意 | 话术优化 |
| **时机判断** | 判断"什么时候该提醒"——已读超时、承诺未兑现、太久没联系 | 未回复提醒、主动推送 |

### AI 如何解决痛点

| 痛点 | AI 解决方式 |
|------|------------|
| 消息遗漏 | 小Q 记住每一个授权好友的对话，生成总结，不依赖用户手动翻聊天记录 |
| 回复拖延 | 已读计时 + 主动提醒，打破"等会儿回"的循环 |
| 表达困难 | LLM 基于上下文和联系人画像实时生成多风格回复，用户只需点选 |
| 群消息焦虑 | 从大量消息中提取"跟我有关"的信息：被 @ 了几次、聊了什么话题 |
| 记忆断片 | 联系人画像持久化存储：性格、偏好、历史约定，随时可查 |

### AI 技术方案

```
┌─────────────────────────────────────────────┐
│                  双轨策略                     │
│                                             │
│  ┌─────────────────┐  ┌───────────────────┐ │
│  │   规则引擎 (本地) │  │   LLM API (远程)   │ │
│  │                 │  │                   │ │
│  │ • 关键词提取    │  │ • 智能回复生成    │ │
│  │ • 话题检测      │  │ • 话术润色        │ │
│  │ • 消息计数      │  │ • 画像更新        │ │
│  │ • 超时判断      │  │ • 推送决策        │ │
│  │ • 内容总结      │  │                   │ │
│  │                 │  │ 模型: DeepSeek /   │ │
│  │ 延迟: <10ms     │  │ 千问 / Ollama      │ │
│  │ 成本: 零        │  │ 延迟: 500ms-2s    │ │
│  └─────────────────┘  └───────────────────┘ │
│                                             │
│  未配置 API → 纯规则引擎，全功能可用          │
│  配置 API → 规则引擎兜底 + LLM 增强           │
└─────────────────────────────────────────────┘ 
```

**技术特点：**

- **离线可用**：规则引擎覆盖所有核心功能，不依赖网络，零延迟
- **按需增强**：配置 LLM API 后自动切换，AI 回复质量显著提升
- **数据本地化**：所有聊天记录、画像、记忆存储在浏览器 localStorage，不经过任何服务器
- **模型无关**：兼容 OpenAI API 格式，支持 DeepSeek、通义千问、Ollama 本地模型等

## 模块四：落地与商业化

### 落地可行性

| 维度 | 评估 |
|------|------|
| **技术可行性** | 高。Demo 已实现全部核心功能，纯前端方案零后端依赖，部署仅需静态文件服务器 |
| **集成路径** | 短期：浏览器插件注入 QQ 网页版。中期：QQ 小程序/内嵌 WebView。长期：客户端原生 SDK |
| **隐私合规** | 默认全部数据本地存储，用户对每个联系人独立授权。LLM 调用仅为可选增强，不上传社交关系 |
| **用户体验** | 非侵入式设计，悬浮球 + 推送 Toast + 小Q 面板三种交互层级，用户掌控开关 |

### 商业化思考

| 阶段 | 方向 | 说明 |
|------|------|------|
| **免费层** | 基础功能全开放 | 智能回复、话术优化、精华提炼、消息提醒（规则引擎），零成本服务 |
| **高级订阅** | LLM 增强 + 更多配额 | 接入 AI 模型后的高质量回复、每日更多推送次数、更长的记忆周期 |
| **企业版** | 工作群/班级群 | 自动会议纪要、任务分配追踪、群活跃度分析、敏感言论预警 |
| **开放平台** | UGC 技能市场 | 第三方开发者可创建自定义 Agent 技能，平台抽成 |

### 关键指标

| 指标 | 目标 | 说明 |
|------|------|------|
| 次日留存 | >40% | 用户第二天是否会再次使用 |
| 功能使用率 | >15% | 至少使用过一个 Agent 功能的用户占比 |
| 提醒采纳率 | >30% | 收到未回复提醒后实际去回复的比例 |
| NPS | >50 | 用户是否愿意推荐给朋友 |

### 风险与应对

| 风险 | 应对 |
|------|------|
| 用户对"被监控"的反感 | 每联系人独立授权，默认关闭；数据全部本地，透明可控 |
| AI 回复质量不稳定 | 规则引擎兜底保证基础体验；用户可选择回复或忽略 |
| 推送过度骚扰 | 每日推送上限 + 负反馈自调节 + 频率限制 |
| LLM API 成本 | 规则引擎覆盖全功能、零成本；API 调用作为增强选项 |
